# `trigger_queries.json` の扱い

**このファイルは JSON 配列**(`run_loop.py --eval-set` に渡す正本)。
**トップレベルにメタデータを足せない**ので、注記はここに置く。

## 🔴 クエリは書き換えないこと

**trigger の `should_trigger` は「ユーザーが何を求めているか」の ground truth であって、
`description` が何を宣伝しているかではない。**

`description` を変えたからといって `should_trigger` を合わせに行くと、eval は
**「description が description 自身と一致するか」**を測るだけの空虚なものになる。

> **description が測られる側で、クエリは物差し。物差しを動かさない。**

## 2026-08-02 の description 改訂について

A/B の結果に合わせて `description` を改訂した(否定された価値を降ろし、差が出た領域を前へ。
詳細は `NOTES.md` §10)。**20 クエリは意図的に変更していない。**

改訂後に `t02`(カードの余白をダークで確認)などが拾われなくなったら、
それは**「description が悪くなった」という測定結果として受け取る**のが正しい。
—— ただし本スキルの A/B では、その領域(カード内部の見た目)は**スキルが効かない**と
測定されているので、**拾われなくなること自体は損失ではない可能性が高い。**

## 次に trigger eval を回す人へ

**旧版と新版の両方に同じ 20 クエリを当て、差分だけを見ること。**
片方だけ測っても改訂の是非は分からない。

- 旧 description(744字版・288字版・406字版)は git 履歴から取れる。
- `run_loop.py` は `--description` で上書きできるので、**同じクエリセットで版だけ差し替えられる。**
- ⚠️ `run_loop.py` は `anthropic` パッケージと API キーを要求する(このセッションでは未導入)。
