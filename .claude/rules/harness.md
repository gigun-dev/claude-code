# harness を触るときに読むもの

**現在地・次の作業は `docs/harness/next-directions.md`(repo ルート相対)にある。
このディレクトリを編集する前に読むこと。** 作業の区切りごとに必ずそちらを更新する
(完了は打ち消し線+✅、状況変化は `> **YYYY-MM-DD 更新:**` を積層。計画は消さない)。

**「着手順」節だけはチェックリスト形式。書式は `/harness:status --help`(= `nd-tasks.sh --help`)
が正 —— ここでは複製しない。** `/harness:status` が機械的に読む唯一の節で、
**`[x]` には証拠行(`→ 何を確認したか`)が要る**(書けない移行時のみ `(移行: 証拠なし)` で免除)。
カタログ部と現在地は従来どおり散文。

## 盆栽の7原則(何を足すかではなく、何が腐るかで決める)

**ハーネスに何かを足す/変える前に、これで採点する。**根拠と実例はカタログ部「盆栽の7原則」。

1. **置き場は「維持義務があるか」で決める。** log.md は時点記録なので腐っても害が無い。
   現在地を表明する文書(ND・ADR 相当)は腐ると嘘になる。義務を負う覚悟が無いなら置かない。
2. **事実と機構は残り、散文は腐る。⚠️ 散文とコードは別の物差しで採点する。**
   - **散文**(SKILL.md 本文・rules・CLAUDE.md・ND): **「その一文はエージェントの行動を
     変えるか。プラスにもマイナスにも」** —— 変えないなら削る。**悪い方へ変えるなら急いで削る**
     (モデルが賢くなるほど、良い既定を上書きする指示は「無意味」から「有害」へ移る)。
   - **コード**(scripts/・hooks): **「そのコードは散文を何行消しているか」。閾値は圧倒的に緩い**
     —— 自然言語よりコードの方がスケールするので、厚みは許される。
     **行数を理由に削るな。**責務の重複・投機的な汎用化・対象の複雑さを超えた賢さを理由に削る。
   **混ぜると必ず誤る**(2026-08-08 に実際に誤った。詳細は `docs/principles.md` 規則2)。
3. **予算を先に置くと規律が要らなくなる。ただし単位は、実際に縛っている機構から取る。**
   頭 8,000字(切り詰めは 10,000字・#70460)かつ ≒3,000 tok(毎セッションの実費)/
   CLAUDE.md ≒2,000 tok / log 1,500行(注入されないので人が読める長さが正しい)。
   **行を予算にしない** —— どの機構も使っておらず日本語率で 2 倍以上ブレる。
   ⚠️ **閾値を上げて警告を消すのは禁止。下げ直すのは可。**
4. **検知器は黙って死ぬ前提で、検知器を検証する。** 0件は「無い」ではなく「壊れた」。
   **それらしい数字は 0件より危険** —— 独立した第二の計測と一度も突き合わせていない数字を
   根拠にしない(ツール失敗を 64 倍に膨らませた誤検知の実例あり)。
5. **強制は最小、検知は最大。** 落とすのは CI 相当の検証だけ。記録・文書系は警告 + 逃げ道。
   ゲートを増やすと「黙って決めて記録しない」に転ぶ。
6. **新機構を足す前に、既存機構で届くか見る。** 足りないのは保存ではなく**到達性**のことが多い。
7. **距離が近いほど効く。ただし距離を詰めるために複製すれば必ずドリフトする。**
   その場に置くのは**事実とポインタ**、正典は1箇所。

主旨は **harness(`plugins/harness/`)の改善** — セッション引き継ぎハーネスを各リポジトリへ
配布するプラグイン。配布物(`skills/doctor/assets/`)を変更したら:

- **バージョン刻印を上げる**(そのファイルの内容が変わった版を書く)。
  刻印はファイルごとに異なるのが正常 — 揃えると配布先の世代差分を検出できなくなる。
- **配布済みリポジトリへの反映は `/harness:doctor` の再実行**(冪等なので既存の正典は壊れない)。
  どこが古いかは `grep -r "harness-template v"` で分かる。
- `skills/doctor/scripts/install.sh` は破壊的、`survey.sh` は読み取り専用。
  **survey.sh だけが SKILL.md の `!` 記法で自動実行される** — この境界を崩さないこと
  (`!` はスキルを読んだだけで無条件に走るため、破壊的スクリプトを置くと事故になる)。
