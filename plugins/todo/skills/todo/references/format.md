# todo.txt の行の読み方（このプラグインの拡張込み）

1 行 = 1 タスク。プレーンテキスト。並べ替えは普通の `sort` で意味が通るように
設計されている（だから優先度と日付が前に、完了印が行頭に来る）。

## open な行（todo.txt）— 3 つの規則

1. **優先度があるなら必ず先頭。** `(A) ` 〜 `(Z) `（大文字 1 字を括弧で括り、空白 1 つ）。
   先頭以外の `(A)` は優先度ではない。`(b)` も `(B)->` も優先度ではない。
2. **作成日は優先度の直後。** `YYYY-MM-DD` + 空白。優先度が無ければ行頭。
   末尾に置いた日付は作成日にならない。
3. **`+project` と `@context` は、優先度／作成日より後ろなら行内のどこでもよい。**
   直前に空白 1 つ、`+` か `@` に続けて空白以外の文字。1 行に 0 個でも複数でもよい。

```
(A) 2026-09-09 送信バッファを A/B する +upload @device dep:a3f9c1 id:7b2e04
2026-09-09 結果を docs へ書く +upload see:docs/x.md id:9291ec
```

## 完了した行（done.txt）— 2 つの規則

1. **行頭が小文字の `x` + 空白。** 大文字 `X` は完了ではない。`xylophone` も違う。
2. **`x` の直後が完了日。** 作成日があればその次に来る（`x <完了日> <作成日> <本文>`）。
   完了日 − 作成日 で所要日数が出る。多くのクライアントは完了時に優先度を落とす
   （このプラグインもそうする。残したければ自分で `pri:A` と書く）。

```
x 2026-09-09 2026-09-08 送信バッファを A/B する +upload id:7b2e04
```

## `key:value`

追加のメタデータは `key:value` で書く。**key も value も、空白とコロンを含めない。**
コロンは 1 つだけ。→ `see:https://example.com` は value にコロンが 2 つ目なので違反。
`todo check` が拾う。

## このプラグインが足しているもの

| 記法 | 意味 |
|---|---|
| `id:7b2e04` | `add` が採番する 6 桁の小文字 16 進（`/dev/urandom` 3 バイト）。**タスクを指す唯一の手段。** 行番号は編集とマージでずれる。連番にしないのは、並行ブランチで採番が衝突するから |
| `dep:a3f9c1` | 依存。カンマ区切りで複数可。指す先が **done.txt に入るまでその行は `ready` に出ない**。todo.txt にも done.txt にも無い id を指していると永久に出ない（`check` が宙吊りとして名指しする） |
| `see:docs/x.md` | 根拠の置き場。**リポジトリ相対パス。** URL は上の `key:value` 規則に反する |
| `@wip` | 進行中の印。`start` が付け、`stop` と `do` が外す。**進行中を優先度で表さない** —— 優先度は重要度の意味のまま残す |

## 並び順

`ls` と `ready` は **優先度（`(A)` が先、無しは最後）→ ファイル内の出現順**。
id は乱数なので id 順に意味は無い。
