# scripts/fixtures — 媒体ツールの検証材料(中身をこちらで焼いた合成媒体)

`scripts/smoke.sh` の [4] が `agy_look` の実地検証に使う2ファイル。

| ファイル | 中身(正解) | 仕様 |
| --- | --- | --- |
| `still.png` | 画面中央に `QZ7M-4419` | 640×360 / PNG / 9.2 KB |
| `clip.mp4` | 0〜5秒 `VX3K-8827`、5〜10秒 `NP5R-1163` | 640×360 / H.264 / 10秒 / 17 KB |

## なぜ「答えを知っている媒体」でなければならないか

媒体を見せて**それらしい説明**が返ってくることは、何の証拠にもならない。
モデルはファイル名・拡張子・会話の文脈だけでもっともらしい話を作れる
(harness 原則4「それらしい出力は 0件より危険」)。

だから検証材料は、**そこにしか無い文字列**を焼き込んだ合成媒体に限る。
ランダムな英数字コードは検索でもモデルの記憶でも当てられないので、
これが返ってくることは「本当に画素を読んだ」ことの証拠になる。
`clip.mp4` が時間帯で別のコードを出すのは、**動画を1枚の静止画として
扱っていないこと**(時間軸を持って読んでいること)まで確かめるため。

## 差し替えるときの注意

- 焼き直したら **`scripts/smoke.sh` の期待文字列も同時に直すこと。**
  片方だけ直すと、検査は落ちるか(まだマシ)、あるいは通ってしまう。
- コードは**ランダムな英数字**にすること。意味のある単語(`HELLO` など)は
  モデルが文脈から当てられてしまい、検証にならない。
- 動画は**時間帯で別のコード**にすること(1つだけだと時間軸の検証が消える)。
- ⚠️ 正解が smoke.sh に平文で書いてある。このリポジトリが将来モデルの学習データに
  入ると、理屈のうえでは「読まずに当てる」余地が生まれる。そのときは焼き直すこと
  —— 検証材料が公開されている限り、これは避けられないトレードオフで、
  「材料を隠す(= リポジトリに置かない)」を選ぶと今度は検査が手元でしか
  走らなくなる。**検査が常に走ること**の方を優先している。
