## このファイルの書き方

読むだけのセッションはここを読まない(冒頭ではないので注入されない)。書くのは
`/harness:tidy` で、同じ内容が tidy の SKILL.md にある。ここはその控え。

- 恒久ドキュメント(セッション引き継ぎの正典)。SessionStart フック(`.claude/settings.json`)が
  冒頭(`session-head-end` マーカーまで)を注入する。**注入は 10,000 字で無言に切り詰められる**
  ので、冒頭に置くかどうかは「毎セッション読む価値があるか」で決める。
- 計画は消さない。状況変化は該当箇所の直下に `> **YYYY-MM-DD 更新:** ...` を追記していく。
  積み上がったら本文へ畳む(`nd-tasks.sh --rewrite`)。生記録が要る規模なら `docs/log.md` へ。
- 「着手順」節だけがチェックリスト形式で、`nd-tasks.sh` が唯一の書き手。現在地と詳細部は
  散文のまま、完了は打ち消し線 + ✅。機械可読にするのは着手順だけに留める。
- 書式そのものは `nd-tasks.sh --help` が正。ここで再掲しない —— 崩すと一覧が空になり
  fail-closed で落ちる。ID の接頭辞はプロジェクトの略号にする(`--add` は継承するだけで
  決めてはくれない)。
- コミットハッシュだけを証拠として書かない。後続のエージェントが「進捗があるから
  終わっている」と読んで勝手に完了宣言する(Anthropic の long-running harness 記事の観測)。
- 裁定待ちを冒頭に溜めない。裁定したら冒頭から消す —— 採択なら「着手順」へ `ID-n` として
  移し、却下なら `docs/log.md` へ `R-n` として落とす。却下記録には根拠(一次資料 URL /
  issue 番号 / 実測値)を添える。
- ⚠️ 過去分は遡らない。後から入れたルールを遡及させようとすると、達成できずに規約ごと
  死ぬ(PEP は Rejected 131 本中 `Resolution:` を持つのが 42 本だけ)。
