# harness:next — 着手順の一覧

## Operating Posture

あなたは**読み取り専用の集計係**。ONE thing しかしない —— `next-directions.md` の「着手順」節を
読んで一覧にする。**1バイトも書き換えない。**

失敗モードは3つ。**上ほど重い**:

1. **0件を「タスクが無い」と報告する。** 本当に空のときと検知器が壊れたときの症状が同じなので、
   0件は**まず「壊れた」を疑う**。非0で落ちたら「タスクが無い」ではなく
   「書式かパーサが壊れている」と明言する(詳細は下の fail-closed 節)。
2. **正典を書き換えて「片付けてしまう」。** 書き手が2つになると正典が割れる。完了の反映も
   整理対象の移動も **`/harness:tidy`** の仕事、健全性検査は **`/harness:doctor`**、
   導入・更新は **`/harness:init`**。
3. **表を要約して項目を落とす。** スクリプトの出力はそのまま見せる(下の Required Output Format)。

**一覧を出すだけで何も直さずに終わるのが正常な実行。** 未移行のリポジトリを見つけても、
この skill は移行しない —— 件数を伝えて終わってよい。

## 使い方

```sh
bash "${CLAUDE_SKILL_DIR}/scripts/nd-tasks.sh"                 # このリポジトリ
bash "${CLAUDE_SKILL_DIR}/scripts/nd-tasks.sh" --all           # ~/ghq/github.com/*/* を横断
bash "${CLAUDE_SKILL_DIR}/scripts/nd-tasks.sh" --format json   # エージェントが読む用
bash "${CLAUDE_SKILL_DIR}/scripts/nd-tasks.sh" --lint          # 書式検査のみ(違反があれば非0)
```

**書式の仕様(読む書式・JSON のフィールド・検査項目・終了コード)は `--help` が正。**
ここには複製しない —— 複製した側だけが古くなる(実際、終了コードは 3 が増えたのに
ここの写しは 0〜2 のままだった)。

`!` 記法(スキル読み込み時の自動実行)は**使わない**。理由は2つ:
このスキルは明示起動なので読み込み時点で走らせる必要が無いことと、
`!` に置けるのは「**必ず成功する**読み取り専用スクリプト」だけという境界を崩さないこと
(nd-tasks.sh は fail-closed で非0終了しうるので、その条件を満たさない)。

### 書き込み(next 自身は書かない。呼ぶのは `/harness:tidy`)

**「着手順」を手で書き換えず、この4つに書かせる。** スクリプトが唯一の書き手であるかぎり
書式ドリフトは構造的に起きない(採番もファイル全体を走査するので、アーカイブ済み ID の
再利用事故が起きない)。以下 `nd-tasks.sh` は上と同じ
`bash "${CLAUDE_SKILL_DIR}/scripts/nd-tasks.sh"` の略:

```sh
nd-tasks.sh --add "<概要>" --criteria "<完了条件>"     # 起票(ID 自動採番)
nd-tasks.sh --done <ID> --evidence "<何を確認したか>"  # 完了(証拠行は必須)
nd-tasks.sh --note <ID> "<本文>"                      # 更新を積層
nd-tasks.sh --archive [--apply]                       # 完了記録へ降ろす(既定 dry-run)
```

## 出力は3区分 — 「もう頭に置かなくていいもの」も出す

出さないと ND が単調増加する。

1. **次にやること** — `[ ]` の項目。**完了条件も一緒に出す**(次に何をすれば閉じられるかが主目的)
2. **完了(証拠あり)** — `[x]` かつ証拠行を持つもの
3. **整理対象** — `[x]` すべて(証拠の有無を問わない)。閉じた時点で「頭」に置く理由が
   消えるので、**カタログ部か `log.md` へ移す候補**という意味

2 と 3 は重複してよい。`(移行: 証拠なし)` は「検証済みとして扱わない」というラベルであって、
整理対象かどうかとは**独立の軸**。

**移すのは `/harness:tidy` の仕事。next は読んで出すだけで動かさない。**

## 「頭」のバイト数 — 横断 board の主要な健康指標

`docs/**/next-directions.md` の先頭から `<!-- session-head-end` までのバイト数を出す。

**SessionStart の stdout は 10KB を超えると無言で切り詰められ、2KB のプレビューだけが
注入される**(anthropics/claude-code#70460)。

- 8,000B 超 → 警告(切り詰めまでの余裕が 2KB を切る)
- 10,000B 超 → **いま実際に切れている**。棚卸しして頭を縮める
- マーカー無し → 頭注入型のフックを持つリポジトリでは**注入が停止している**(違反)。
  pointer 型フックのリポジトリでは注入自体が無いので警告に留まる

⚠️ **閾値を上げて警告を消すのは禁止。** 棚卸し後に現況へ下げ直す方向のみ可。

## fail-closed — 0件で落ちたら「タスクが無い」ではない

**項目0件をタスク無しと解釈してはいけない。** ただし0件の理由は2つあり、扱いが違う:

| 理由 | 判定 | 意味 |
|---|---|---|
| **未移行**(`no-section` / `not-migrated`) | 単一では違反 / **`--all` では警告** | 節が無い、または `- [` 行が1本も無い = まだチェックリストにしていない。**既知の状態で異常ではない** |
| **ドリフト**(`empty-section` / `malformed`) | **常に違反** | `- [` 行はあるのに読めない = **前は読めていたものが読めなくなった**。本物の異常 |

`--all` でだけ未移行を警告に落とすのは、横断 board を毎日叩くものだから ——
未移行が1つでもあると常に赤になり、**赤の意味が消えて本物のドリフトが埋もれる**
(閾値を上げて警告を消すのを禁じているのと同じ理屈。検知は「鳴りっぱなし」でも死ぬ)。
未移行の件数はサマリ行に必ず出るので、「まだやっていない」ことは数字で伝わる。

落ちたら `--lint` で原因を見て、**書式かパーサのどちらを直すべきかを報告する**。

検査項目: `[x]` の証拠行欠落 / ID 重複 / 項目行に見えるのに ID が取れない行
(= 書式ドリフトの検知器)/ マーカー欠落 / 未移行 / ドリフト。

## Required Output Format

スクリプトの出力(markdown の表)を**そのまま人に見せる**。要約して項目を落とさない。
そのうえで、必要なら次の1〜2行だけを添える:

- 3区分の件数(`次にやること N / 完了(証拠あり) M / 整理対象 K`)
- 頭のバイト数が閾値を超えているファイルがあれば、その事実と `/harness:tidy` への誘導
- 違反(非0終了)があれば、**「タスクが無い」ではなく「書式かパーサが壊れている」と明言する**
- `--all` で未移行があれば件数だけ添える(**警告であって失敗ではない**。移行は `/harness:init`
  で配られる新テンプレートの書式に合わせて ND を書き換えるだけ)

## 組み込みタスクリストへ流し込むとき

未完了項目を `TaskCreate` で投入してよい。**ただし md → タスクリストの一方通行に限る。**

**タスクリスト側の変更を ND へ書き戻してはいけない。**「どちらが本当か」を後から判定
できなくなる。ND の更新は本文を編集して行い、その反映は `/harness:tidy` の仕事。
タスクリストはあくまでそのセッション中の作業メモとして使う。

## 関連

- **`/harness:tidy`** — セッションを畳む。正典の更新・整理対象の移動・コミット・push まで。
- **`/harness:doctor`** — 設定がベストプラクティスを守れているかの静的検査。
- **`/harness:init`** — ハーネスの導入・更新(冪等)。
