# harness:init — プロジェクトハーネスの導入

caldav / swift-mcp-app で実証済みのセッション引き継ぎハーネスを対象リポジトリへ導入する。

## この skill の作り(重要)

**機械的にできることは全部 `scripts/install.sh` が行う。** 散文手順をモデルに解釈させると
実行のたびに揺れる(手順の読み飛ばし・chmod 忘れ・settings.json の壊し方が毎回違う)。
あなたに残る仕事は**判断だけ** — コード配置の特定、検証コマンドの選定、現在地の文章化。
判断結果を引数でスクリプトに渡し、作業そのものはスクリプトに任せること。

スクリプトは冪等。導入済みリポジトリへ新版を配るのにも同じコマンドを使う。

## 設計原則(なぜこの形か)

- **すべて対象リポジトリへコピーする。** 導入後はこのプラグインへのランタイム依存が無い。
  目的は Claude Code のメモリー機構への依存を減らすこと — メモリーはプロジェクトスコープで
  git 外・マシン依存・他エージェント不可視。リポジトリ内ファイルなら git 管理で履歴が残り、
  remote 実行や別マシンでも同じ文脈が立ち上がる。
- **エージェント可視性は2層で正直に扱う。** md ファイルの実体はどのエージェントからも読める。
  自動ロード(頭注入・rules のパススコープ)は実装依存だが、Codex は `.codex/` アダプタで
  **同じフックスクリプトを共有できる**(caldav で実証済み。`--with-codex`)。
- **セッション開始時の注入は「頭」だけ。** 全文注入は毎セッション高コストなアンチパターン。
  マーカーが無いときは全文注入にフォールバックせず警告して止まる(fail-closed)。
- **運用契約は検知器で支える。** 「必ず更新する」は宣言だけでは腐るので、フックが
  カタログ肥大化・頭の肥大化・現在地の日付 vs 最終コミット日の乖離を機械計測して警告する。
- **pre-push はローカルで止める。** 個人開発では branch protection を admin が bypass
  できるため、サーバー側は実効的でない。**make は前提にしない**(あれば使うだけ)。

## 手順

### 1. 調査(ここだけが判断の仕事)

- **コード配置**: rules の `paths:` に渡す glob を決める。⚠️ **言語に合っていないと一度も
  マッチせず silent に無効化される**(swift-mcp-app で 2026-07-22 に実際に起きた)。
  TypeScript なら `src/**,test/**,migrations/**`、Swift なら `Sources/**,Tests/**` など、
  実際にディレクトリを見て決めること。
- **検証コマンド**: pre-push で走らせるもの。**CI と同じ内容にする**(手元で通って CI で
  落ちるなら関門の意味がない)。省略すると package.json / Makefile から自動検出する。
  重い工程(ネットワークや認証を要する deploy dry-run 等)を含むなら、push のたびに
  待たされてよいかユーザーに確認する。
- **docs/ の用途**: GitHub Pages / VitePress / Docusaurus 等の公開サイトソースなら、
  next-directions.md(内部の意思決定・ボツ案を含む)が公開されてしまう。`--docs-dir` で変える。
- **起動ルート**: フックは claude を起動したディレクトリ基準。モノレポでサブディレクトリから
  起動する運用なら、そこを起点に実行する(ルートに置くと無言で不活性化する)。
- **Codex 併用の有無**: `.codex/` があるか、ユーザーが Codex も使うか。
- 現在地の材料集め: README・直近コミット・会話の文脈から「今どこにいて、次に何をするか」。

### 2. スクリプト実行

```sh
<skill_dir>/scripts/install.sh --code-paths "src/**,test/**" [--check-cmd "bun run check"] \
  [--docs-dir docs] [--with-codex] [--skip-prepush]
```

`<skill_dir>` はこの SKILL.md があるディレクトリ。cwd は対象リポジトリなので絶対パスで呼ぶこと。
スクリプトが「実行した機械的作業」と「残りの作業」を出力する。

### 3. 残りの作業(スクリプトが出した □ を埋める)

スクリプトの出力が正。以下は各項目の説明:

- **next-directions.md の `{{CURRENT_STATE}}` / `{{NEXT_STEPS}}` / `{{CATALOG}}`** —
  手順1で集めた材料から書く。現在地は「未コミットの実装がある」「裁定待ちの判断がある」など
  次のセッションが知らないと困ることを具体的に。捏造しない。
- **rules の `{{REPO_SPECIFIC_HOTSPOTS}}`** — このリポジトリで経緯コメントが特に効く場所
  (外部 API の非公式な叩き方、ドメインの癖、チューニング値など)。リポジトリを読んで書く。
- **CLAUDE.md** — 無ければ作る(200行以下: 一行説明 / 主要コマンド / アーキテクチャ要点)。
  あれば以下の定型2節を追記する:

```markdown
## 情報の書き分け方針

- **コード = How** / **テスト = What** / **コミットログ = Why** / **コメント = Why not**。
- **コメントはコードと同量レベルでベッタベタに書く。** 詳細は `.claude/rules/comments.md`
  (コード編集時に自動ロード)。

## 現在地・次の作業(セッション引き継ぎ)

- 正典は **`docs/next-directions.md`** — SessionStart フック(`.claude/settings.json`)が
  頭(`session-head-end` マーカーまで)を自動注入する。作業の区切りごとに必ず更新
  (完了は打ち消し線+✅、変化は `> **YYYY-MM-DD 更新:**` を積層。計画は消さない)。
```

- **README に `git config core.hooksPath .githooks`** — `.git/config` に入るため git 管理
  されず、**clone ごとに1回必要**。セットアップ手順に含めないと誰も有効化しない。
- **既存 next-directions.md が旧様式の場合** — 上書きせず、既存本文をカタログ部へ移し、
  頭(現在地・着手順)を新設し、行頭に `<!-- session-head-end -->` を入れる。

### 4. 検証

- `bash .claude/hooks/session-start.sh` — 頭(マーカーまで)だけが出ること。
- マーカー行を一時的に消して警告モード(fail-closed)になるのも確認して戻す。
- pre-push: `echo "refs/heads/main $(git rev-parse HEAD) refs/heads/main $(git rev-parse HEAD)" | .githooks/pre-push`
  で検証が走ること(`git push --dry-run` ではフックは走らない)。
- 大規模・長期プロジェクトなら `docs/log.md`(追記専用アーカイブ)の新設も提案する。
  小規模なら git 履歴で足りるので作らない。

### 5. 報告

作成・変更したファイルと、next-directions.md に書いた現在地の要約をユーザーに示す。
**コミットはユーザーの指示があってから。**

## 注意

- **個人リポジトリ前提。** チーム共有リポでは `.claude/settings.json` + フック .sh のコミットが
  「clone した全員のセッション開始時に実行されるコード」になる(settings.json のコマンド文字列を
  変えずに PR で .sh の中身だけ差し替えられる)。導入前にユーザーへ確認すること。
- **配布物のバージョン刻印は「そのファイルの内容が最後に変わった版」**。ファイルごとに
  異なるのは正常で、揃えてはいけない(揃えると配布先で世代差分を検出できなくなる)。
  配布先の世代確認は `grep -r "harness-template v" <repo>`。
- 導入後にビルトイン `/init` を実行すると CLAUDE.md が定型2節を持たない形で上書きされうる。
  実行してしまった場合は手順3の2節を復元する。
