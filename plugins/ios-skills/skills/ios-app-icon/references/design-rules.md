# Liquid Glass アイコンの設計原則と、案の出し方

## システム効果と素材固有の光学表現を分ける

Appleの既定方針に合わせ、importする素材はflatで輪郭の明確なlayerにする。blur、shadow、specular、
bevel、glow、opacity/translucency effect、背景色やgradient、iOS角丸maskは素材から外し、
Icon Composerへ任せる。生成AIの一枚絵に付いたテカリ、角丸、全体shadowも除去する。

custom gradient、rim light、環境影などを使うのは、ユーザーの意図やブランド上の理由が明確な
例外だけにする。その場合は`native-look.md`を実験例として読み、6 appearanceと対象OSの実機で
system effectsとの二重掛けや可読性低下がないことを検証する。

## 造形の制約

- **シェイプ数を絞る。** Apple 自身が「過剰な複雑さ」を最も多い失敗として名指ししている。
  屈折はシェイプの数・大きさ・重なりに敏感で、小さい形・細い線は潰れて汚くなる。
  目安は 2〜4 個。
- **前景は白〜near-white の単色**にすると Tinted モードでコントラストが保証される。
- 背景はベタ、または `system-light` / `system-dark` などシステム提供の値。
  Tinted 時はカスタムグラデより素直に出る。
- 文字・数字・ロゴタイプは入れない(SVG を使うならアウトライン化)。
- キャンバスは 1024×1024(watchOS のみ 1088)。**アートは中央 ~832px の安全域に収める。**

## iOS 26 の実物から読める設計言語

`scripts/extract_apple_icons.sh` で純正アイコンを抜いて並べると、思い込みが壊れる。
実際に確認できること:

- **背景は白/淡色が主流**(カレンダー・リマインダー・ヘルス・ファイル)。
  ブランド色のベタ塗り一択は古い型で、メッセージなど一部だけ。
- **前景は多色でよい**(リマインダーの青赤橙のドット、ウォレットの3色カード)。
- **意味を説明しない。** カレンダーは日付を数字でなくドット格子で抽象化している。
- **ショートカットが Liquid Glass の見本**。濃紫背景に半透明の角丸菱形が2枚重なるだけで、
  重なりの透過そのものがデザインになっている。**重なりの語彙は最も「iOS 26 らしく」出る**
  —— システムが重なりを屈折させるので、重ねること自体が効果になる。

「吹き出し = チャット」「リング = カレンダー」のような**説明的ピクトグラムは古びて見える**。
機能を説明するのではなく、抽象的な記号と構成で成立させる方向を先に試す。

## 案の出し方(実地で効いた順序)

1. **参照を作る。** 先に純正アイコンを抽出して並べる。これをやらずに案を出すと、
   自分の思い込み(=たいてい一世代前の設計言語)に沿ったものしか出てこない。
2. **複数案を同時に出す。** 1案ずつ見ると全部それなりに見えてしまう。3〜6案を
   `contact_sheet.swift` で並べ、**必ず実サイズ(120pt / 80pt)と一緒に**判断する。
   1024px で成立していても 80pt で潰れる案は多い。
3. **ictool でレンダリングしてから評価する。** 素材の見た目と最終的な見た目は別物。
   ガラスがかかると印象が変わるので、素材段階での判断は当てにならない。
4. **難点が見えたら、見せる前に直す。** 「ここが惜しい」と分かっているものを出すと、
   相手の時間を使って同じ指摘を受けるだけになる。
5. **自己評価を添えて出す。** どれが良いと思うか、なぜか、どこが弱いかを言う。
   相手は「どれがいい?」より「この評価は妥当か」の方が判断しやすい。

## 画像生成 AI との分業

gpt-image のような画像生成は**構図の発想を広げる用途では有効**だが、返ってくるのは
**合成済みのラスター1枚**なので、そのままでは `.icon` のレイヤーに分解できない。

有効な形:

1. 生成 AI に「ベタ塗り背景 + 白い平面シルエットが数個」という制約を明示して案を出させる
   (制約を書かないと必ず光沢と3D表現が乗ってくる)
2. 気に入った構図を選ぶ
3. **その構図を透過レイヤーとして描き起こす**(`draw_layers.swift`)
4. `.icon` にして ictool で確認

生成物をそのまま appiconset に入れる手もあるが、レイヤー分離を捨てることになるので、
Liquid Glass の効果は浅くなる。

## はみ出しは目で判断しない

回転はシェイプの外接矩形を対角方向へ膨らませる。角度・サイズ・位置を同時に見積もるのは
人間には無理で、実地では手で座標を詰めて**3世代連続ではみ出した**(右端 1024px まで
溢れているのに気づかなかった)。

`draw_layers.swift` は毎回 bbox を実測して安全域を検査し、`autofit` で中央寄せ +
安全域いっぱいへスケールする。これは「余白を詰めたい」という要求にも自動で応える。
