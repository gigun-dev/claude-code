# 純正の質感を出す(グラデーション・透明感・多層の立体感)

作った案が「素材は正しいのに安っぽい」「Liquid Glass に頼っているだけに見える」ときに読む。
純正アイコン(ショートカット、ブック)が持っていて自作案に無いものは、**モチーフではなく
6つの光学的な処理**であることが多い。ここではそれを実測して分解し、SVG で再現する。

## 1. 何を測ったか

Simulator ランタイムから抽出したショートカットを 9×9 でサンプルすると、背景は
**単一色相の縦グラデーション**だった(ほぼ等間隔・上が明るい)。

```
上 #502896 → #4d2791 → #48258b → #432485 → #3e227e → #392078 → #341e70 → #2f1c69 → #2d1b66 下
```

前景の板は 1 枚の中で色相をまたぐグラデーション(`#fca7e5` → `#cb6abe` → `#9f4eb4` →
`#595bca`)を持ち、**半透明で重なった所が第3の色として合成**されている。

ここから取れる差分は6つ。自作案に足りていないのはたいていこれ:

| # | 要素 | 効果 | 無いとどう見えるか |
| --- | --- | --- | --- |
| 1 | 背景のグラデーション | 1つの光源の下に置かれて見える | 印刷物のように平たい |
| 2 | 面ごとの多段グラデーション | 面がガラスの板に見える | 紙を切り抜いて貼ったように見える |
| 3 | 重なりでの色の合成 | 層が本当に重なっていると読める | ただの前後関係 |
| 4 | **リムライト(縁の光)** | **ガラスに見える最大の要因** | 塗り絵 |
| 5 | 背景色を帯びた環境影 | 同じシーンの中にある | 貼り付けたステッカー |
| 6 | 背後の淡いハロー | 面が浮く | 背景に沈む |

`icon.json` の `specular` / `translucency` を有効にしても、**素材が不透明なベタ塗りなら
3 も 4 も起きない**。システムの効果は素材の性質を増幅するだけで、無いものは作らない。

## 2. レシピ(そのまま貼れる SVG)

`render_svg.swift` で描く前提。`viewBox="0 0 1000 1000"`。

### defs

```xml
<defs>
  <!-- 1. 背景。単一色相のまま明度だけ落とす + 端を沈める放射のかぶせ -->
  <linearGradient id="bg" x1="0" y1="0" x2="0" y2="1">
    <stop offset="0"   stop-color="#4a44b0"/>
    <stop offset=".55" stop-color="#332e86"/>
    <stop offset="1"   stop-color="#221d5c"/>
  </linearGradient>
  <radialGradient id="vig" cx="34%" cy="24%" r="92%">
    <stop offset="0"  stop-color="#6a63d8" stop-opacity=".45"/>
    <stop offset=".6" stop-color="#000000" stop-opacity="0"/>
    <stop offset="1"  stop-color="#000000" stop-opacity=".38"/>
  </radialGradient>

  <!-- 2. 面のグラデーション。光は左上から。3〜4 段取ると平たさが消える -->
  <linearGradient id="gFace" x1=".12" y1="0" x2=".9" y2="1">
    <stop offset="0"   stop-color="#ffffff"/>
    <stop offset=".45" stop-color="#f4f3ff"/>
    <stop offset="1"   stop-color="#c9c8ee"/>
  </linearGradient>

  <!-- 4. リムライト。上辺〜左上で白く、下へ抜ける -->
  <linearGradient id="rim" x1=".1" y1="0" x2=".8" y2="1">
    <stop offset="0"   stop-color="#ffffff" stop-opacity=".95"/>
    <stop offset=".38" stop-color="#ffffff" stop-opacity=".28"/>
    <stop offset="1"   stop-color="#ffffff" stop-opacity=".05"/>
  </linearGradient>

  <!-- 5. 環境影 / 6. ハロー -->
  <filter id="amb"  x="-45%" y="-45%" width="190%" height="190%">
    <feGaussianBlur stdDeviation="17"/></filter>
  <filter id="halo" x="-60%" y="-60%" width="220%" height="220%">
    <feGaussianBlur stdDeviation="60"/></filter>
</defs>
```

### 1枚の面を「ガラスの板」にする

同じ形を3回描く。影 → 本体 → 縁の光。これが最小単位で、面を増やすときも繰り返すだけ。

```xml
<g data-layer="03-card">
  <!-- 影: 背景色を帯びた濃色を少し下へずらしてぼかす(純黒にしない) -->
  <g transform="translate(6,16)" opacity=".5">
    <rect x="..." y="..." width="..." height="..." rx="66"
          transform="rotate(13 cx cy)" fill="#150f3c" filter="url(#amb)"/>
  </g>
  <!-- 本体: グラデーション + 半透明(重なりで下の色と合成される) -->
  <rect x="..." … fill="url(#gFace)" fill-opacity="0.88"/>
  <!-- 縁の光: 同じ形を塗らずに線だけ -->
  <rect x="..." … fill="none" stroke="url(#rim)" stroke-width="6"/>
</g>
```

**`fill-opacity` は前面ほど下げる**(例: 奥 0.96 / 中 0.94 / 前 0.86)。
ショートカットは前の板越しに後ろの板が見えることそのものがデザインなので、
一番手前を不透明にすると効果が消える。

### レイヤー分割との対応

`.icon` は層ごとに別 PNG が要るので、**面 1 枚 = `data-layer` 1 つ**にして、
その面の影とリムライトは同じグループに入れる(位置がズレない)。
背景とハローも独立した層にするが、**この2つは `icon.json` で `"glass": false` にする**
(理由は下記)。

## 3. やってはいけないこと(実際にやって失敗した)

### 小さい要素すべてにグラデーションを掛ける

網点の一つ一つに放射グラデーションを掛けたら、網点ではなく**飴玉**になった。
純正は Health のハート、iCloud の雲、Files のフォルダのように**主役の1形状**だけが
多段グラデーションを持ち、Reminders の3つの点や Passbook のカード端のような
小さい繰り返し要素は**ベタ塗りのまま**。表現力が増えたぶん、掛ける場所を選ぶ。

ただし**小さい要素でも「影」と「縁の光」は足してよい**。この2つは面を球にしないので
飴玉にならず、点が浮いて層として読めるようになる。区別の基準はこう:

| 処理 | 小さい繰り返し要素に | なぜ |
| --- | --- | --- |
| 塗りに放射グラデーション | **不可** | 面が球になる = 飴玉 |
| 環境影(背景色を帯びた影) | 可 | 面は平たいまま、位置だけ持ち上がる |
| リムライト(線として) | 可 | 縁だけが光る。塗りは平たいまま |
| 場全体に掛ける照明グラデ | 可 | 個々ではなく塊に掛かるので粒が球にならない |

### ぼかした層を `"glass": true` にする

ぼかしたハローや発光をガラス板として扱わせると、**システムが縁に鏡面反射を付けて
硬い輪郭が出る**。ぼかしを強めるほど目立つ。背景・グロー・ハローは `"glass": false`。

### 「色を並べる」ことで多色にする

同じ平面に色を並べても、構成を変えるだけでは全部同じ絵に見え続ける。純正が多色を
出すときは必ず深さがある(Wallet の重なったカード端、Passwords の3本の鍵、
Shortcuts の重なった半透明の菱形)。**多色は層の違いとして出す**。

### 素材の見た目で判断する

`_composite.png` が良くても、`ictool` を通すと別物になる(グラデーションに鏡面反射が
乗ると金属光沢になる、など)。**必ずレンダリングして、実サイズ込みで見る。**

## 4. 案出しの進め方(迷走を避ける)

70 案以上を出して当たり率が 0 だった探索から得た規律。

- **モチーフごと総取っ替えを繰り返さない。** 1 案ごとに構造・配色・技法を同時に変えると、
  良かった点も一緒に捨ててしまい何も積み上がらない。当たりを引くまでの乱数試行になる。
- **良い案が出たら基準に固定し、軸を1つずつ動かす。** 「点の大きさ」「配置」「配色」
  「glass の値」を別々に振って、どれが効いたかを言えるようにする。
- **却下された理由を蓄積して次に持ち込む。** 「彩度が高すぎる」「斜めの境界」「背景が黄ばむ」
  のような指摘は、次の案の制約として明示的に書き出す。
- **綺麗だが無意味 / 意味はあるが不格好 の両方が失敗。** 曲線的で複雑な形は綺麗になるが、
  アプリと関係なければ「花に見える」で終わる。逆にモチーフが正しくても造形が弱ければ落ちる。
- **行き詰まったら案を足さず、参照を求める。** 「この既存アイコンの雰囲気で」と実例を
  もらえれば設計言語を抽出して当てられる。弱いのは造形の発想であって再現ではない。

## 5. 成果物だけでなく生成元を残す

`.icon` は `icon.json` + PNG で、**幾何は PNG に焼き込まれている**。つまり後から
「カードを少し動かす」「回転を変える」ができない。編集できるのは `icon.json` に書いた
色・効果・重なり順だけ。

したがって **`.icon` の隣に生成元(spec JSON か SVG)を必ずコミットする**。
PNG はビルド生成物であり、それだけを残すのはコンパイル済みバイナリだけを
コミットしているのと同じ状態になる。

```
Resources/
├── AppIcon.icon/        ← 成果物
│   ├── icon.json
│   └── Assets/*.png
└── AppIcon.svg          ← 生成元。これが無いと作り直すしかない
```
