## 2026-08-06 外部調査 第2バッチ(subagent 9本)

「harness」がバズワード化して competitor が
出ている前提で、語彙・競合・配布機構・引き継ぎ慣習を横断調査した。以下は**事実として
確定した分**。未裁定の判断は next-directions の頭へ上げる。

### プラグイン常駐フックは発火する(CC 2.1.222 で実測)

検証用プラグインを作り
`--plugin-dir` / `directory` marketplace の user・local スコープの3経路すべてで、
フック実行と stdout のコンテキスト注入を確認。`CLAUDE_PROJECT_DIR` と cwd も正しい。
`directory` ソースは**キャッシュではなくソースを直読み**する(ソース側だけ書き換えたら
新しい方が注入された)。つまり `session-start.sh` は1文字も変えずに常駐化できる。
ただし issue #11509 は NOT_PLANNED の stale 自動クローズで、修正コミットは存在しない
(#10997 / #11939 / #12634 / #14410 も同じ末路)。**「直った」のではなく「誰も返事を
しなくなった」だけ。**

- `R-2` **却下: プラグイン常駐への全面移行** — それでも**全面移行はしない**判断。理由3つ: (1) チーム・別マシン・CI にプラグインは
  無く、git に載る settings.json と違って「入れた人限定」になる (2) #12151 で 2.1.96 →
  2.1.97 の**無言の回帰**が報告済み。フックが黙って死ぬとハーネスは「現在地が注入されない
  まま普通に動く」ので気づけない (3) #76297 でプラグイン側と settings.json 側に同じ
  コマンドがあると重複排除されず**二重実行**される。

**結論: 二層化。**プラグインには「検出と警告」だけ常駐させ(未導入・hooksPath 未設定・
世代が古い)、ハーネス本体はコピーのまま。「コピーをやめる」のではなく「**コピーが
壊れていることを検出する層**」を常駐させる。

### SessionStart の stdout は 10KB で無言に切り詰められる(#70460, open)

超えると
2KB のプレビューだけが注入され、**警告は出ない**。`HEAD_MAX_LINES=80` は行数の閾値
なのでバイト数では守れていない。実測(2026-08-06):
`figmate 8,256B` / `tiktok-fetcher 7,305B` が射程内、`docs/harness 6,074B` が接近中。
→ nd-tasks.sh に頭バイト数の計測を入れる(8KB 警告 / 10KB 強い警告)。

### マーカー欠落で注入が停止しているリポジトリがある

`tdr-concierge` は
`session-head-end` が無く、頭の注入が停止したまま誰も気づいていなかった。fail-closed が
正しく働いた結果だが、**停止したことを誰にも伝えていない**のが問題。
この repo の `docs/ios-skills/next-directions.md` も同じくマーカー無し。現状は pointer 型
フックがマーカーを見ないため実害ゼロだが、**テンプレート版を当てた瞬間に止まる**潜伏状態。

### 世代刻印は測定対象を取り違えている

install.sh の配布物は3クラスに分かれている:
無条件上書き(session-start.sh, pre-push, codex-hooks.json)/ 存在したらスキップ
(comments.md, next-directions.md, log.md, codex-README.md)/ 冪等マージ(settings.json,
.gitignore, config.toml)。**上書きクラスは再実行で必ず最新になるので grep しても差が
出ず、スキップクラスは差が出るが更新する手段が無い。**つまり
`grep -r "harness-template v"` は「更新できるものには差が出ず、差が出るものは更新
できない」組み合わせを見ている。comments-rule.md は作成以来1コミットなので未顕在だが、
次に更新した瞬間に効く。加えて版数空間が3つに分裂(plugin.json 0.10.0 / コミット
メッセージ v0.6.0 / ファイル刻印 v0.2.0〜v0.3.0)、配布物7件中**刻印があるのは3件だけ**。
→ 対案は `.claude/harness-manifest.json`(version + commit SHA + installed ファイル一覧
+ install 時のオプション)。世代が単一値になり、`--code-paths` 等の**引数が永続化**され、
`installed` があるので**廃止ファイルの削除**も可能になる。業界の定石もこちら
(copier `.copier-answers.yml`、cruft `.cruft.json`、pre-commit の `rev`)。
Go の `DO NOT EDIT` や projen のヘッダは**版数を含まない**「編集するな」の宣言で、
世代管理とは別物。

- `R-3` **見送り: copier への乗り換えは現時点で見送り** — 3-way merge のベースを `old_copy/` に実ファイル
  として持つ設計は cruft より堅い(cruft は blob 依存で、**改変されている=更新が最も必要な
  場面でこそ 3-way が失敗**する。issue #47)。cruft は 2024-12-25 以降停止、作者が

## 2026-08-08 切り詰めを知らせる検知器が、切り詰めによって死んでいた

使えないので、計測に依存する警告は必然的に末尾へ行く。**計測と印字を分けたら順序が
自由になり、印字は `sed` で足りるようになった**(awk は集計だけに縮小)。
