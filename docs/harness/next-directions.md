## 設計の根拠(敵対的検証で確定したもの)

v0.1.0 に対し観点を分けた3体(実行系を実際に壊す / 公式仕様へ接地 / 設計レッドチーム)で
敵対的検証を実施し、21指摘のうち14を採用した。**深刻度「高」の指摘2件は偽陽性**で、
公式ドキュメントの原文引用と本番実績で棄却している(指摘は裁定するもので、従うものではない)。

採用して現在の設計に入っているもの:

- **fail-closed**: `session-head-end` マーカーが無いとき、全文注入にフォールバックせず
  警告して止まる。旧設計は「全文注入 + 肥大化検知の同時無効化」が起きていた。
- **行頭アンカー**: マーカー検出を `^<!-- session-head-end` に。散文中で言及しただけで
  頭が切断される誤爆を防ぐ。
- **計測は寛容に、教える書式は厳密に**: 更新ブロックのカウントは太字省略・スラッシュ日付も
  数える。書式が少しズレただけで腐敗検知が静かに死ぬ設計にしない。
- **鮮度検査**: 現在地の日付 vs 最終コミット日。「必ず更新する」は宣言だけでは腐るので、
  検知器で支える。括弧は全角/半角両対応(caldav では全角のため一度も効いていなかった)。
- **閾値の上げ方向調整を禁止**: 警告を消す最小コスト行動が「棚卸しではなく閾値引き上げ」に
  ならないようにする(唯一の自動フィードバックがラチェット式に無効化されるのを防ぐ)。
- **バージョン刻印**: 配布先の世代を grep で追える。**刻印は「そのファイルの内容が最後に
  変わった版」**なのでファイルごとに違うのが正常。揃えると差分を検出できなくなる。

未解決のまま残っている指摘:

- **運用契約の強制機構は無い**(検知器のみ)。Stop フックや pre-commit で「コード変更あり・
  ND 未更新」を検査する案は未実装。過剰に感じるので保留中。
- **チーム共有リポでの安全性**: `.claude/settings.json` + フック .sh のコミットは
  「clone した全員のセッション開始時に実行されるコード」。settings.json のコマンド文字列を
  変えずに PR で .sh の中身だけ差し替えられる。個人リポ前提と注意書きしてあるだけ。

## harness:doctor(第2の skill)

設定がベストプラクティスを守れているかの機械検査 + 判定基準へ立ち返るための文脈。
> **2026-08-05 更新:** 当初 audit(手順書)と doctor(検査)に分けたが、どちらも「診る」で
> 冗長だったため doctor へ統合した(cclens の doctor/optimize/query が*動詞*で分かれていて
> 重複しないのを参考にした)。腐敗対策は2段:

1. **結論ではなく手順を保存する** — 事実の根拠は実行時にライブ取得する(ベストプラクティス
   記事・公式ドキュメント)。腐るのは結論で、手順は腐りにくい。
2. **賞味期限** — SKILL.md 冒頭に「最終検証日 + 180日を超えたら枠組み自体を再検証」。

`references/` に日付付きスナップショット(初回監査結果・敵対的検証の方法・テレメトリ方針・
国内メガベンチャーの o11y 実施状況)。次回監査でライブ状態との差分を見る材料。
