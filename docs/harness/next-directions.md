## 盆栽の7原則(2026-08-07 確定)

**ハーネスに何かを足す/変える前に、これで採点する。**圧縮版が
`.claude/rules/harness.md` にあり、`plugins/harness/**` と `docs/harness/**` を触ると自動で届く
(原則7を、この原則自身の配送に適用している)。

すべて**この repo で実際に壊れた事例**から出ている。順序は独立で、上位ほど効くわけではない。

### 1. 置き場は「正しさを維持する義務があるか」で決める

| | 維持義務 | 腐ったときの症状 |
|---|---|---|
| `log.md` | **無い**(その時点の記録) | 古くなるだけ。害が無い |
| コメント | 弱い(コードと一緒に動く) | コードと乖離すると嘘になる |
| `next-directions.md` | **ある**(現在地を表明する) | 嘘になる |
| ADR 相当 | **ある** | 嘘になる。しかも誰も気づかない |

Write the Docs の「**誤ったドキュメントは無いより悪い**」が適用されるのは維持義務がある側だけ。
log.md が安いのはここ(Simon Willison の temporal documentation —— 通常のドキュメントは
「将来の更新義務」を伴うが、時点記録は伴わない)。

**使い方**: 書きたくなったら「これは維持しないと嘘になるか」を先に聞く。嘘にならないなら
log.md、なるなら**維持コストを払う覚悟があるか**を確認してから置く。
→ ADR を入れなかった判断はこの一点(実測: ADR ログの 78.7% が1年以上放置、
24.6% が30日以内に停止。MADR 本家ですら 19本中3本しか `status:` を運用していない)。

### 2. 事実と機構は残り、散文は腐る

AHE(arXiv:2604.25850)の ablation —— ハーネスを7コンポーネントに分け、種に1つだけ差した:

| 差したもの | Terminal-Bench 2 |
|---|---|
| memory のみ | 75.3% |
| tool のみ | 73.0% |
| middleware のみ | 71.9% |
| **system prompt(= 散文)のみ** | **67.4%(唯一の退行)** |
| 種(何も差さない) | 69.7% |

> factual harness structure transfers across tasks and models whereas **prose-level strategy does not**

Claude Code 作者も「半年ごとに CLAUDE.md も skills も hooks も全部消して、モデルが何をするか
見ろ」と言っている。ETH の A/B(arXiv:2602.11988)の「指示は従われるが概観は効かない」も同型。

**使い方**: 書くのは罠(`idb ui tap` は外しても exit 0)・実測値(753s vs 852s)・機構
(ゲート、検知器、スクリプト)。**「まず〜を検討せよ」「慎重に判断すること」は書かない。**

### 3. 予算を先に置くと、規律が要らなくなる

頭を 8KB に縛った結果、「根拠は log、頭は裁定待ちだけ」という書き分けが**自動的に強制された**。
実際 2026-08-07 に項目を足したとき 9,189B になって検知器に捕まり、削らざるを得なかった。

**制約が判断を代行する。**判断に任せると必ず膨らむ。

⚠️ **閾値を上げて警告を消すのは禁止。下げ直すのは可。**上げ方向を許すと検知がラチェット式に
静かに死ぬ。現行の予算: 頭 **8,000字**(#70460 / #84021 で 10,000字 超は無言に切り詰め)かつ
**≒3,000 tok**(毎セッションの実費)/ CLAUDE.md **≒2,000 tok** / log 1,500行
(全文ロードの費用から。実測で caldav が 1,424行 / 146KB とすぐ手前)。

> 規則8。⚠️ **実効は緩和側だった**(頭は旧 97% → 新 51%)。緩和だという事実は隠さない。
> log の 1,500行 が行のままなのは意図的 —— **log は注入されない**ので守っているのは
> 「人が読み通せる長さ」で、それは実際に行で決まる。**単位は機構ごとに選ぶ。**

### 4. 検知器は必ず黙って死ぬ。だから検知器を検証する

このリポジトリで実際に起きた空振り:

- 鮮度検査の正規表現が2リポジトリで一度も発火していなかった(全角括弧の件を直した後の**再発**)
- `survey.sh` の世代検出が、自分の説明文を拾って `harness-template v (未導入)` を出していた
- **`docs/harness/log.md` の見出しが、数時間前に書いた自分の規約に違反していた**
- 頭のバイト数を測るとき、本文に `session-head-end` と書いたせいで grep が誤爆した
  (実装側は行頭アンカーでこれを防いでいた)

**共通の症状は「エラーが出ない」こと。**だから **0件は「無い」ではなく「壊れた」として扱う**
(`nd-tasks.sh` は「タスクが無いと解釈してはいけない」と出して落ちる)。
そして **規約を書いた本人が守れているかを機械が見る。**

### 5. 強制は最小、検知は最大

「a rule is only hard if a hook blocks it」は正しい。だがゲートを増やすと逆効果になる、という
一次証言が正面から対立している:

> ゲートが無いから死ぬ —— "no gate → writing one is volunteer work. That's why they die."
> **ゲートがあるから死ぬ** —— "if the document has to be approved, then people
> **quietly make decisions without recording it anywhere**."

changesets 公式も「changeset が無いことでブロックすることは**推奨しない**」と明言し、
`--empty` の逃げ道を用意している。

**使い方**: 落とすのは **CI 相当の検証(pre-push の型・テスト)だけ**。記録・文書系は
**警告 + 明示的な逃げ道**(`- (記録不要: 定型作業のみ)` がそれ)。

### 6. 新機構を足す前に、既存機構で「届くか」を見る

ADR の件が典型だった。診断はこう:

- 却下記録は**既に書けていた**(copier 見送りの理由は PEP 3103 の却下通知より詳しい)
- 置き場も**既にあった**(log.md)
- **無かったのは ID と索引だけ**

**問題は保存ではなく、編集地点での到達性だった。**新しいディレクトリを作っても到達性は
改善しない。

### 7. 距離が近いほど効く。ただし距離を詰めるために複製すれば必ずドリフトする

Tailwind が勝ったのは「このクラスは何をするのか / どこで定義されているか」を調べる**往復が
消えた**から。コンポーネントを1つ読めば全部わかる。エージェントには**2つ目のファイルを
開かせない**ことが効く。

同じ構造が繰り返し出ている:

> **ADRs, Notion docs, and Confluence pages die because they're separate from the code.
> Out of sight, out of mind.**

Write the Docs の原則にも1項目ある —— "**Nearby**: Store sources as close as possible to the
code which they document."。ETH の「指示は効くが概観は効かない」も距離で説明がつく:
**編集地点に届く指示は行動に接続されるが、セッション開始時に届く概観は何にも接続されていない。**

**ただし代償がある。**Emil Kowalski のスキル群は自己完結のため値を7ファイルに複製し、結果
frequency 表が3文言に、scale 下限が3種に分裂した。Tailwind がこれを回避しているのは
**値(design token)を1箇所に集め、表現(utility class)だけをその場に置いている**から。

**使い方**: その場に置くのは**事実とポインタ**。正典は1箇所。
`.claude/rules/*.md` が「テンプレートの先頭が正(複製しない)」と書いているのがこの形。

### この7原則で採点した結果(2026-08-07)

| 提案 | 判定 | 効いた原則 |
|---|---|---|
| log.md の見出し移行 + 索引 | やる | 1(義務なし)・6(既存機構) |
| 却下に `R-n` の ID + 却下索引 | やる | 6(無いのは ID だけ) |
| 「裁定待ち → 却下は log へ」 | やる | 1(ND から義務が減る) |
| `paths` 付き rule に却下理由を3行 | やる | 7(編集地点に届く)・2(事実) |
| **ADR ディレクトリ新設** | **やらない** | 1(義務が増える)・6(到達性が改善しない)・7(遠い) |
| **pre-push で log 欠落を fail** | **警告どまり** | 5(隠れるようになる) |

却下案は**アンカーがあるならコードコメント**(curl の "We used to close the filters ... however
that complicates filter code" が実例)。アンカーが無いもの(「copier に乗り換えない」等)だけが
log.md + `R-n` に落ちる。

## 方針の外部検証(2026-08-05 調査)

**結論: 乗り換え先は無い。harness の思想は業界の現在地と一致している。**
変えるべきは思想ではなく (1) 配り方 (2) 頭に注入する中身の性質 (3) 検知器そのものの検証。
**価値の本体は規約側にあり、配布物は薄いほど良い。**

- **ETH Zurich [arXiv:2602.11988](https://arxiv.org/abs/2602.11988)** — SWE-bench Lite +
  実物の AGENTS.md を持つリポジトリでの A/B。「コンテキストファイルは成功率を改善せず、
  推論コストを平均 20% 以上増やす」「**指示はよく従われるが、リポジトリ概観は役に立たない**」。
  エージェントが従わないのではなく、従っているのに概観が効かない。
- **[Anthropic: Effective harnesses for long-running agents](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)** —
  「後続のエージェントが進捗を見て、勝手に完了と宣言する」観測。対策は
  「E2E 検証が通ってから初めて passes を立てる」。**harness の「完了は打ち消し線+✅」様式が
  直撃する罠。**
- **memory bank 系は上流ごと死んだ** — Roo-Code は 2026-05-15 archived、メンテナが
  「Memory banks don't work without significant manual maintenance」と明言。
  `roo-code-memory-bank` の作者本人が md 方式を捨てて MCP+RAG へ移行。
- **agent-os は自作機構を捨てた** — v3 で「spec 執筆は Plan mode、タスク分解は todo list に
  任せる」とし、残したのは standards の索引化と選択的注入だけ = `.claude/rules/` と同じ結論。

**SDD との関係**: 似て非なるもの。SDD の spec は「これから何を作るか」を実装**前**に書く
駆動文書で正典は仕様側にあるが、ND は「今どこにいるか」を作業**中**に書く状態文書で
正典はコード側にある。時制と権威の向きが逆。上記の agent-os の撤退と ETH の結果は、
むしろ**重い spec 層を持つことへの警告**として読む。共通点は「タスクの明文化を人間の記憶では
なくファイルに置く」の一点だけ。

**ドキュメントの置き場の序列**(この序列が設計判断を決める):
①コードの近くにコメント → ②全体像の最小限を repo の docs → ③跨ぐ経緯は Issue/PR コメント。
③が限度。**跨ぎの経緯だけは①②で受けられないので外に出す**(report.sh がこれ)。

## 設計の根拠(敵対的検証で確定したもの)

v0.1.0 に対し観点を分けた3体(実行系を実際に壊す / 公式仕様へ接地 / 設計レッドチーム)で
敵対的検証を実施し、21指摘のうち14を採用。**深刻度「高」の指摘2件は偽陽性**で、公式
ドキュメントの原文引用と本番実績で棄却している(指摘は裁定するもので、従うものではない)。
方法は `plugins/harness/skills/doctor/references/adversarial-verification.md`。

- **fail-closed**: マーカーが無いとき全文注入へフォールバックせず警告して止まる。
- **行頭アンカー**: 散文中で `session-head-end` に言及しただけで頭が切断される誤爆を防ぐ。
- **計測は寛容に、教える書式は厳密に**: 書式が少しズレただけで腐敗検知が静かに死ぬ設計にしない。
- **鮮度検査**: 現在地の日付 vs 最終コミット日(ただし不具合1で空振り中)。
- **閾値の上げ方向調整を禁止**: 警告を消す最小コスト行動が閾値引き上げにならないように。
- **バージョン刻印**: 「そのファイルの内容が最後に変わった版」。ファイルごとに違うのが正常。

未解決の指摘: 運用契約の強制機構は無い(検知器のみ)。チーム共有リポでは
`.claude/settings.json` + フック .sh のコミットが「clone した全員のセッション開始時に
実行されるコード」になる(個人リポ前提と注意書きしてあるだけ)。

### doctor の指摘のうち、このリポジトリでは却下するもの

**⚠️ 却下は理由を書かないと、次のセッションが同じ指摘を再発見して再判断する**
(`doctor/SKILL.md` の Operating Posture)。ここがその記録。

- **「CLAUDE.md が無い」→ 却下。**複数プラグインの寄せ集めなので、**全プラグインに常時
  ロードすべき横断の事実がほとんど無い。**関心は `.claude/rules/<component>.md` の
  `paths:` 付きに寄せてあり、触っている間だけ生きる形になっている(規則1「情報は寿命で
  置き場を決める」)。CLAUDE.md を作れば**サブエージェント起動回数ぶん乗算で払う**ものが
  増えるだけで、届く先が広がらない。**この構成が変わる(横断の常時ルールが実際に要る)まで
  再検討しない。**
- **`--lint` の `[head-costly]`(頭が予算超過)→ 保留。**この警告は**頭が毎セッション
  注入される前提**で書かれているが、このリポジトリのフックは pointer 方式なので**頭は
  注入されていない。**つまり指摘の前提がここでは偽。ただし頭が肥大していること自体は
  事実(`H-5` の棚卸し対象)なので、警告そのものは消さない。検査側を pointer 方式に
  対応させるかは `H-22` と同型の判断になるため、そちらと合わせて決める。
