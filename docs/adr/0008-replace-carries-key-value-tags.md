# `replace` は key:value タグを持ち越す

Date: 2026-09-10

`replace` は本文だけを書き換えてタグを捨てていた。2026-09-10 に esp32-airdrop-poc で
測定の前提が変わるたびに 5 行を言い直し、そのうち 1 行で **`dep:` が消えて依存が誰にも
告げられずに解けた**（言い直した直後にその塞ぎを当てにしていたことに気づいた）。todo.txt の
仕様は `key:value` を追加のメタデータと定めており、行の本文（`+project` と `@context` を
含む）とは別物である。よって `replace` は仕様どおりの `key:value` トークンをすべて持ち越し、
外すのは**操作者が key を書いたとき**だけとする —— 新しい本文で同じ key を上書きするか、
`--drop KEY` で名指しする。どちらの経路でも消えた key は stderr で名指しされる。書式は
増やさない。代償として、タグは行末へ寄り、本文中の位置は保たれない。

これを覆すのが高いのは、この規則がこれから各リポジトリの行の形を決めるからだ。タグが行末に
並び、操作者はタグが残ることを前提に言い直すようになる。後から「やはり落とす」に戻すと、
その前提で書かれた行が黙って壊れる。

Rejected: `dep:` があるのに新しい本文に無ければ拒む（`see:` など他のタグに一般化できず、
同じ根から次の症状が出る）。タグを行の元の位置に保つ（本文を置き換える以上、位置は復元できない）。
`+project` と `@context` も持ち越す（仕様がこの 2 つを本文の一部と定めている）。
