# `replace` は key:value タグを持ち越す

Date: 2026-09-10
Implementation: done

`replace` は本文だけを書き換えてタグを捨てていた。esp32-airdrop-poc で測定の前提が変わるたびに 5 行を言い直し、そのうち 1 行で `dep:` が消えて依存が誰にも告げられずに解けた。

todo.txt の仕様は `key:value` を本文と別物と定めているので、`replace` は仕様どおりの `key:value` トークンをすべて持ち越し、外すのは操作者が key を書いたとき(新しい本文で上書きか `--drop KEY`)だけにする。どちらの経路でも消えた key は stderr で名指しされる。

これを覆すのが高いのは、この規則がこれから各リポジトリの行の形を決めるからだ。タグが行末に並び、操作者はタグが残る前提で言い直すようになるので、後から戻すとその前提で書かれた行が黙って壊れる。

Accepting: タグは行末へ寄り、本文中の元の位置は保たれない
Rejected: `dep:` があるのに新しい本文に無ければ拒む — `see:` など他のタグに一般化できず、同じ根から次の症状が出る
Rejected: タグを行の元の位置に保つ — 本文を置き換える以上、位置は復元できない
Rejected: `+project` と `@context` も持ち越す — 仕様がこの 2 つを本文の一部と定めている
