# 前提が崩れた行は `do` ではなく `@dropped` で閉じる

Date: 2026-09-10

「前提が間違っていた」はこのプラグインを使う仕事で最も多い結末の一つで、2026-09-10 の
esp32-airdrop-poc の一日だけで 3 件出た（測る段では 2 つのフラグが同一の挙動になり比較が
存在しなかった、機体とビルドの組み合わせという仮説が焼き直しで消えた、通す先の経路が
読んだら無かった）。それまで出口は `do` しか無く、**やっていない仕事が `done.txt` に完了として
並んでいた**。`drop ID "理由"` を足し、完了行に `@dropped <理由>` を付けて閉じる。印は
todo.txt の context ひとつ、理由は行末の散文で、書式は増やさない（他の todo.txt クライアントからは
完了行 + context として読める。`todo.sh` で確認した）。理由は必須 —— 理由の無い drop は `do` と
読み分けられず、「終わった」と嘘をつくのと同じだけ記録を汚す。`done.txt` に「これから」以外の
ものが入るのはこの理由だけで、経緯と学びの置き場はコミットメッセージと docs のまま。

drop した id は `dep:` を解く。前提が死んだなら、それに依存していた行も読み直す必要がある
公算が高く、人の前に出すほうが永久に隠すより良い。

Rejected: 理由を任意にする（`do` と区別が付かない）。`done.txt` とは別のファイルに落とす
（保管場所は todo.txt と done.txt の 2 つだけ、という約束を崩す）。行に過去の文面を溜める
（todo.txt に腐る散文を持たない、に反する。`replace` は消す前の行を stderr に出すだけにして、
残したい経緯はコミットメッセージへ移す）。
